Google says "this app isn't verified". Is it safe to continue?

Yes. That warning appears because the script is your own private copy, and Google has no public listing to verify. You are not installing someone else's app; you are granting your own script access to your own Gmail and Sheet. Click Advanced, then Go to (your project) (unsafe), then Allow. See Setup step 2.

Telegram buttons do nothing, or I see a webhook / 401 error

The Web App URL almost certainly ends with /dev instead of /exec. Telegram cannot log in to /dev, so it gets rejected. Copy the URL from Deploy > Manage deployments (not the test URL), then re-run Deal Watch > Setup and paste it. Setup refuses a /dev URL, so you will know immediately. If you need to replace a URL that was already stored, clear the webapp_url row in Script Properties and run Setup again.

I set up a rule but I get no notifications

Check these in order:

  • The rule is enabled (open /list and tap the rule).
  • The sender matches the email: a domain rule uses the part after the @, an email rule must match exactly.
  • A keyword really appears in the email body, not just the subject.
  • Enough time has passed. The default interval is 15 minutes, and a check with no matches sends nothing.
  • /status shows the last check time and any error.

Settings or Ideas will not open

The Mini App opens from a button the bot sends, and that link is short-lived. If it expired, send /setai again for a fresh button. It also only opens for the bound owner account, so open it on your own Telegram account, not a shared device signed in as someone else.

I get too many notifications

Narrow your rules. Use full email addresses instead of whole domains, and choose more specific keywords. Disable a rule you no longer need from /list instead of deleting it, so you can switch it back on later. Deal Watch has no quiet hours by design; mute the chat when you want a break.

Does it read all my email? Where are my keys?

Deal Watch searches only for mail from the senders you configured, using Gmail's own search. It reads the body of those candidates to check for keywords. It does not scan your whole inbox.

Your bot token, and your OpenRouter key if you set one up, live in your own Google account's script properties. They are never shown in full, never written to the Sheet, and never sent anywhere except to Telegram and OpenRouter, which is how notifications and ideas work. Each person runs their own copy, so nobody else has access to your keys.

What does "three consecutive send failures" mean?

If Telegram rejects three digest sends in a row, Deal Watch stops retrying so it does not spam failures. It keeps checking, and resumes sending once a send succeeds. The last error is always visible via /status. A common cause is a rotated or revoked bot token; fix it with /connect.

How do I stop or delete Deal Watch?

To stop temporarily, disable all rules from /list, or delete the time-based trigger in the script's Triggers screen. To remove it completely, delete the Google Sheet copy you made (its script goes with it) and delete your bot in BotFather with /deletebot. Nothing else is left behind.
